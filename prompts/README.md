# 判断规则与提示词库

这里沉淀可迁移的**判断标准**，不是声称适用于所有人的固定答案。每个模板都应说明适用范围、证据标准、排除项、不确定处理方式和版本。

## 目录

- [Jev 一手实战 / Jev in practice](jev-first-hand.md)：寻找有实现细节和失败边界的 Jev 使用报告。
- [产品需求线索 / Product needs](product-pain-points.md)：寻找有场景、频率和替代做法的用户问题。
- [有依据的技术内容 / Evidence in technical posts](technical-evidence.md)：优先可检查、可复现的技术材料。
- [通用模板](general-template.md)：把一个模糊的信息需求变成可复用规则。
- [实战经验筛选](first-hand-practice.md)：寻找有实际操作与证据支撑的经验帖。

## 如何使用

前三套规则均提供可直接复制的中文与英文目标、判断主体及虚构边界用例。分别粘贴到扩展设置的两个输入框即可；想先理解效果，可打开[免安装示例演示](https://kelaocai.github.io/tweet-radar/)。

The first three rules include copyable English goals and reader profiles, plus fictional examples. Paste each into its matching extension setting. Explore the [interactive sample in English](https://kelaocai.github.io/tweet-radar/?lang=en) before installing.

复制模板后，把方括号内容改成你的任务；用几条虚构或授权样例检查边界，再逐步修订。将你使用的**规则版本**和人工复核结果一起记录，避免把某个模型的一次概率当成金标准。

欢迎提交新主题、反例和评估方法。请不要提交 API key、私信、未公开信息或未脱敏的真实帖子。
