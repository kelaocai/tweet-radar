# 判断模型、采集边界与提示词设计

[返回首页](../README.md) · [English](#english)

## 项目要积累什么

我们想共建的是一套**关于信息如何被发现、筛选和判断的开源知识库**，而非某个模型的“万能提示词”。一个好规则应该说清：筛选目的、受众、可观察证据、排除项、不确定时怎么处理，以及如何验证规则有没有帮助。

插件是免费且可替换的客户端示例。未来这套规则也可以用于人工阅读、脚本、其他浏览器扩展或不同判断服务。

## 边界原则

1. **尊重来源规则与访问边界**：当前插件只读取用户在 X 页面上已经加载的 DOM，不登录、不模拟接口、不自动翻页或点开帖子。
2. **范围有上限**：批大小、每页条数和最佳匹配候选数都有限制。扩展前先评估请求量与服务费。
3. **模型做窄判断，代码做确定工作**：模型判断语义相关性；代码负责阈值、计数和排序汇总。
4. **评论不等于事实核验**：评论区内容可以提供讨论线索，不自动证明原帖可信。
5. **让人最终决定**：显示判断信号和证据线索，不自动发布、转发或采取外部行动。
6. **将信号与事实分开**：互动量、账号身份和模型概率都不能单独证明内容真实性。

## 提示词的四个组成部分

- **目标（goal）**：要找什么具体信息？结果要用于什么任务？
- **判断主体（profile）**：谁在筛选？需要怎样的深度、语境或经验？
- **命中证据（positive evidence）**：哪些可观察要素会使内容有用？例如具体步骤、原始数据、时间范围、可复现材料。
- **排除项（reject / negative evidence）**：哪些属于关键词碰撞、纯营销、无证据断言、重复转述或离题内容？

避免使用“高质量”“有价值”“专业”等未定义词。不要只提供正向关键词；写明反例和噪音。规则应针对内容，而不是针对特定身份群体进行歧视性排序。

## 可复制的模板

```text
目标：寻找【主题/问题】中可用于【实际用途】的帖子。
判断主体：【角色/知识背景】；最需要【信息类型/证据】。
命中标准：
- 与目标有直接关系，并提供【具体证据/经验/步骤】。
- 能区分亲历、引用、推测与宣传。
排除或降权：
- 仅出现关键词，但没有回答目标问题。
- 纯转发、引流或情绪表达，缺少可核查的信息。
- 证据不足或语境缺失时，标记为“需人工复核”，不推断为事实。
```

## 插件中的判断阶段

插件先对每条帖子发出一个二元相关性判断（Noul），之后可以对最多 12 个入围候选做成对比较（Choice）。成对结果由程序按概率加总生成排序。模型概率是一种信号，不是“正确概率”；热度也不等于内容价值。

有多种独立质量维度时，可考虑先分别判断“证据具体性”“可复现程度”“是否一手经验”等维度，再由使用者明确权重；对于不可补偿的红线，应作为独立的排除条件，而不是和其他优点平均。

## 规则质量检查

新规则贡献最好附上脱敏的正例、边界案例和反例，并回答：

- 两位读者是否能理解同一标准？哪些词仍然含糊？
- 规则是否把作者影响力、点赞数或观点立场误当成证据？
- 规则能否处理讽刺、引用、广告、跨语言和缺少上下文的内容？
- 有哪些“看似命中但其实不命中”的反例？
- 如何由人复核误判？能否记录规则版本并说明适用范围？

所有示例应使用虚构文本或已获授权、经过脱敏的内容，不要上传他人私信、未公开信息或含个人敏感信息的样本。

TypeSafe 官方参考：[Noul](https://docs.typesafe.ai/primitives/noul)、[Choice](https://docs.typesafe.ai/primitives/choice)、[HTTP API](https://docs.typesafe.ai/api)。这些接口与模型能力可能更新，集成时请以官方文档为准。

## English

This repository aims to build a reusable, community-reviewed library of information curation boundaries, criteria, prompts, and examples. A good rule names its goal, audience, observable evidence, exclusions, uncertainty handling, and evaluation method. A model probability is a signal, not truth or an accuracy guarantee; human review remains essential.
